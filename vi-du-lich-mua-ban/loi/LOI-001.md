# LỖI 001: App tắt ngay khi mở

## Hiện tượng

Cài `app-debug.apk` (bản build 13/11/2026 15:56) lên Samsung S22 Ultra. Bấm biểu tượng app thì app không mở được. Lỗi không phụ thuộc thiết bị, máy Android nào cũng bị.

## Nguyên nhân (đã xác nhận)

`MainActivity` lấy ViewModel bằng `by viewModels()`, không truyền factory. Factory mặc định (`AndroidViewModelFactory`) tạo `AndroidViewModel` bằng reflection, và cần một constructor **chỉ nhận đúng một tham số** `Application`.

`app/src/main/java/com/lichmauban/app/ui/main/MainViewModel.kt` dòng 51–54:

```kotlin
class MainViewModel(
    application: Application,
    private val clock: Clock = Clock.system(StatsEngine.VN_ZONE),
) : AndroidViewModel(application)
```

Tham số mặc định của Kotlin **không** sinh ra constructor `(Application)` trên JVM. Kiểm tra bằng `javap -p` trên `app/build/tmp/kotlin-classes/debug/com/lichmauban/app/ui/main/MainViewModel.class` chỉ thấy:

```
public MainViewModel(android.app.Application, java.time.Clock);
public MainViewModel(android.app.Application, java.time.Clock, int, kotlin.jvm.internal.DefaultConstructorMarker);
```

Vì vậy factory ném `RuntimeException: Cannot create an instance of class MainViewModel` ngay lần đầu `mainViewModel` được dùng (trong `setContent` / `onStart`), và app tắt.

## Yêu cầu sửa

1. Sửa sao cho có constructor `(Application)`. Cách được khuyến nghị:
   ```kotlin
   class MainViewModel @JvmOverloads constructor(
       application: Application,
       private val clock: Clock = Clock.system(StatsEngine.VN_ZONE),
   ) : AndroidViewModel(application)
   ```
   Cách khác (tự viết `ViewModelProvider.Factory`) cũng được, miễn đúng mục 7 của đặc tả (vẫn inject được `Clock` khi test).
2. **Thêm unit test chống tái phát** (chạy trên JVM, không cần thiết bị). Ví dụ: kiểm tra `MainViewModel::class.java.getConstructor(Application::class.java)` tồn tại. Làm tương tự cho mọi `AndroidViewModel` khác nếu có.
3. Rà soát các lỗi khác có thể làm app tắt khi khởi động: khởi tạo Room/DataStore, gọi mạng trên main thread, theme, Navigation. Ghi những gì đã rà vào `TIEN-DO.md`.
4. Build lại `assembleDebug`. Chạy lại `testDebugUnitTest` (phải đạt toàn bộ, kể cả test mới).

## Khi xong

Thêm mục mới lên đầu `TIEN-DO.md` với tiêu đề có chữ `LOI-001`. Ghi: đã sửa gì, kết quả test, thời gian build của APK mới. **Không** sửa file này. Điều phối sẽ tự kiểm tra lại và đổi trạng thái.

Lưu ý: unit test hiện tại không phát hiện được lỗi này vì chỉ kiểm tra `StatsEngine`. Từ nay, mốc nào có thay đổi giao diện hoặc ViewModel thì phải có ít nhất một test xác nhận ViewModel tạo được bằng factory mặc định.
